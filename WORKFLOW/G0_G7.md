# G0–G7 — controlled Child workflow

| Gate | Required activity | Deliverable | Approval boundary |
|---|---|---|---|
| G0 | Owner pilot ID, scope, rights, classification, acceptance | FORMS/INT-01.md, DEC-01.md | Document intent, do not assume PDF rights |
| G1 | Read Parent/Core 10 + Child 10, version/rights evidence | SOURCES/SOURCE_REGISTER.md, READ_CONFIRMATION.md | A read check is not Core approval |
| G2 | Domain method, contracts, risks, output schema | CORE, METHODOLOGY, RISK_REGISTER | Reviewable draft only |
| G3 | Forms, samples, substantive conversion method, tests | FORMS, EXAMPLES, tools | No invented real ebook data |
| G4 | Generate Markdown-first independent ZIP at archive root | Pack and SHA-256 Manifest | All files/links accounted |
| G5 | Clean extraction; independent static/negative/synthetic checks | QA/TEST_REPORT.md | Technical QA != Business UAT |
| G6 | Propose specific repo Private/main; Owner supplies URL; inspect before Git Bash upload; Owner pushes; verify remote | GIT_HANDOFF.md | No automatic GitHub writes |
| G7 | Independent domain review and Owner decision | GOVERNANCE/DECISION_LOG.md | Separate acceptance and release |

No P2 promotion. A full G0–G5 request does not grant runtime or repository upload rights. Manifest SHA-256 excludes itself; Git tree-only does not validate byte hashes.
